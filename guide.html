관리판 토큰 발급 안내

관리판이 내 GitHub 계정으로 이슈를 읽고 쓰려면 토큰이 필요합니다. 토큰은 이 관리판에만 주는 비밀번호 같은 것입니다. 한 번 만들어 붙여 넣으면 같은 브라우저에서는 다시 넣을 필요가 없습니다. 10분 정도 걸립니다.

누구인지 골라 해당 안내만 따라 하세요.

저장소 주인 (Dong)GameMaker 저장소를 만든 사람. fine-grained 토큰을 씁니다. 함께 작업하는 사람 (Wan)초대받아 참여하는 사람. classic 토큰을 씁니다.
GitHub 화면은 영어로 나옵니다. 아래에서 회색 상자 안의 글자가 화면에 보이는 버튼·칸 이름 그대로입니다.

저장소 주인 (Dong): fine-grained 토큰

이 저장소 하나에만, 필요한 권한만 주는 토큰입니다.

  1. GitHub 에 로그인한 상태에서 토큰 만들기 화면을 엽니다.
    토큰 만들기 화면 열기
    직접 찾아가려면: 오른쪽 위 프로필 사진 → Settings → 왼쪽 맨 아래 Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
    비밀번호나 인증 코드를 다시 물으면 입력합니다.
  2. 이름과 기간을 정합니다.
    Token name 칸에 slime-manager 라고 씁니다.
    Expiration 에서 90 days 를 고릅니다. 기간이 끝나면 이 안내대로 다시 만들면 됩니다.
    Description 은 비워 둬도 됩니다.
  3. 토큰 주인을 확인합니다.
    Resource owner 가 DongDongLim 인지 봅니다. 다른 이름이면 눌러서 DongDongLim 으로 바꿉니다.
  4. GameMaker 저장소만 고릅니다.
    Repository access 에서 Only select repositories 를 누릅니다.
    아래에 생기는 Select repositories 를 누르고 GameMaker 를 검색해 체크합니다.
  5. 권한 세 가지를 켭니다. (가장 많이 틀리는 단계입니다)
    Permissions 아래 Repository permissions 를 펼칩니다.
    목록에서 Issues 줄을 찾아 오른쪽 Access: No access 를 눌러 Read and write 로 바꿉니다.
    Pull requests 줄도 Read and write 로 바꿉니다 (PR 탭에서 승인).
    Contents 줄은 PR 탭에서 병합까지 하려면 Read and write, 보기만 하려면 Read-only 로 바꿉니다.
    목록 대신 + Add permissions 버튼이 보이면, 눌러서 Issues, Pull requests, Contents 를 체크해 추가한 뒤 위처럼 각각 바꿉니다.
    Metadata: Read-only 는 자동으로 붙습니다. 그 밖의 권한은 건드리지 않습니다.
  6. 토큰을 만듭니다.
    맨 아래 Generate token 을 누릅니다. 확인 창이 뜨면 한 번 더 Generate token 을 누릅니다.
  7. 토큰을 복사합니다.
    github_pat_ 로 시작하는 긴 글자가 나옵니다. 오른쪽 복사 아이콘을 눌러 복사합니다.
    이 글자는 지금 한 번만 보입니다. 창을 닫았다면 같은 화면에서 토큰을 지우고 처음부터 다시 만드세요.
  8. 관리판에 붙여 넣습니다. → 아래 「관리판에 넣기」

함께 작업하는 사람 (Wan): classic 토큰

GameMaker 는 Dong 의 개인 저장소라서, 다른 사람은 fine-grained 토큰으로 접근할 수 없습니다 (GitHub 의 제한). 그래서 classic 토큰을 씁니다.

먼저: 저장소 초대 (Dong 이 한 번)

  1. Dong: GameMaker 공동 작업자 설정을 열고 Add people 을 누른 뒤, Wan 의 GitHub 아이디를 입력해 초대합니다.
  2. Wan: 메일로 온 초대를 수락하거나, 초대 수락 화면에서 Accept invitation 을 누릅니다.

토큰 만들기 (Wan)

  1. GitHub 에 로그인한 상태에서 classic 토큰 만들기 화면을 엽니다.
    classic 토큰 만들기 화면 열기
    이 링크로 열면 이름(Note)은 slime-manager, 권한은 repo 가 미리 체크되어 있습니다.
    직접 찾아가려면: 프로필 사진 → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → Generate new token (classic).
  2. 기간을 정합니다. Expiration 에서 30 days 를 고릅니다.
    classic 토큰은 Wan 이 들어갈 수 있는 모든 저장소에 쓸 수 있으므로 기간을 짧게 둡니다.
  3. 권한을 확인합니다. Select scopes 에서 repo 가 체크되어 있으면 됩니다. 다른 것은 체크하지 않습니다.
  4. 토큰을 만듭니다. 맨 아래 초록색 Generate token 을 누릅니다.
  5. 토큰을 복사합니다. ghp_ 로 시작하는 글자 옆 복사 아이콘을 누릅니다.
    이 글자도 지금 한 번만 보입니다.
  6. 관리판에 붙여 넣습니다. → 아래 「관리판에 넣기」

관리판에 넣기

  1. 관리판 위쪽 설정 탭을 엽니다. 설정 바로 가기
  2. GitHub 토큰 칸에 붙여 넣습니다 (Mac: ⌘V, Windows: Ctrl+V).
  3. 나는 에서 본인 이름(Wan / Dong)을 고릅니다.
  4. 저장 을 누른 뒤 토큰 확인 을 누릅니다. 모든 줄이 PASS 면 끝입니다.
  5. 처음 한 번만 (Dong): 필요한 라벨 만들기 를 누릅니다. 두 번째 사람부터는 필요 없습니다.
토큰은 지금 쓰는 브라우저에만 저장됩니다. 다른 컴퓨터나 휴대폰에서 열면 그 기기에서 한 번 더 붙여 넣으세요. 같은 토큰을 써도 됩니다.

GameMaker 저장소가 보이지 않습니다Dong: 4단계에서 GameMaker 를 고르지 않았습니다. Wan: 초대를 수락하지 않았습니다Dong: 토큰 목록에서 해당 토큰을 눌러 저장소를 추가합니다. Wan: 초대를 수락합니다
기획서를 읽을 수 없습니다Contents 권한이 없습니다Dong: 5단계 Contents 를 Read-only 로 바꿉니다
저장할 때 「권한이 없습니다」Issues 가 Read and write 가 아닙니다Dong: 5단계 Issues 를 Read and write 로 바꿉니다. Wan: repo 를 체크해 새로 만듭니다
PR 을 읽을 수 없습니다 / PR 을 승인·병합할 수 없습니다Pull requests 권한이 없거나, 병합에 필요한 Contents 쓰기가 없습니다Dong: 5단계 Pull requests 를 Read and write, 병합하려면 Contents 도 Read and write 로 바꿉니다
repo 권한이 없습니다classic 토큰에서 repo 를 체크하지 않았습니다위 링크로 다시 만듭니다 (repo 가 미리 체크됨)

이미 만든 fine-grained 토큰은 토큰 목록에서 이름을 눌러 저장소와 권한을 고칠 수 있습니다. 고친 뒤에도 토큰 글자는 그대로라 다시 붙여 넣을 필요가 없습니다.

지켜 주세요

  • 토큰은 비밀번호와 같습니다. 메신저·메일·이슈 댓글에 붙여 넣지 마세요.
  • 공용 PC 에는 넣지 마세요. 넣었다면 관리판 설정의 토큰 지우기 를 누르고, GitHub 토큰 목록에서 그 토큰을 삭제(Delete)합니다.
  • 토큰이 새어 나간 것 같으면 바로 GitHub 토큰 목록에서 삭제하고 새로 만듭니다.
